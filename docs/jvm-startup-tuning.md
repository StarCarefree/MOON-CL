# 保守 JVM 启动调优

## 改动范围

启动器过去总是添加 `-Xmn`，将年轻代固定为最大堆的 15%。现在仅当 Java 为 **21 或更新版本、64 位、参数明确启用 G1** 时，停止自动追加这一限制，让 G1 自行调整年轻代。Java 17 及更旧版本、32 位 Java、其他 GC、外置参数文件或无法可靠分析的参数组合沿用原行为。

如果用户或整合包已经设置 `-Xmn`、`NewSize`、`MaxNewSize`、`NewRatio` 或 G1 年轻代比例，启动器不再追加 `-Xmn` 覆盖它们。这条优先级规则对新旧 Java 都适用。

不修改已有配置，不切换 Java 或 GC，不改 `-Xmx`、`-Xms`、锁定内存、JIT、认证或安全参数。新旧版本 JSON 的参数生成路径使用相同策略。

## 已验证的效果和限制

本机 Java 21 的交替微基准中，使用 `-Xmx4096m`、G1、保留原有 `-XX:-UseAdaptiveSizePolicy`，只取消自动 `-Xmn614m`：

- JVM 初始堆从 620 MiB 降至 382 MiB；这是堆容量，不是整个游戏进程的工作集。
- 内存分配探针的进程总耗时中位数从约 438 ms 降至 404 ms。它不是 Minecraft，也不能据此承诺整合包提速比例。
- 年轻代 GC 次数增加，实际吞吐与暂停行为取决于游戏负载。Java 17 的同类探针未显示明确提速，因此未启用该版本的自动调优。

Java 17 和 21 的真实进程检查已验证默认参数、手工 `-Xmn` 和 `NewRatio` 能启动，同时保留指定的初始堆和最大堆。自动化参数测试覆盖版本/位数边界、其他 GC、带引号的属性、参数文件和用户年轻代参数。

尚未测量真实整合包启动到主菜单、长时间游玩、帧率或峰值内存；不能保证每个整合包都更快，也不承诺零风险。

## 回退

没有迁移或删除用户配置。如果特定 Java 21+ 实例出现退化，可在该实例的附加 JVM 参数中显式恢复原先的年轻代大小。举例：最大堆为 `4096m` 时，旧值为 `-Xmn614m`（向下取整的 15%）。启动器会尊重这一显式设置。最大堆变化时应同步调整；移除该显式设置即可再次使用自适应策略。

## 回归命令

从仓库根目录执行，使用安装了 .NET 10 SDK 的 `dotnet`：

```powershell
dotnet test .\PCL.Core.Test\PCL.Core.Test.csproj -c Release --filter 'FullyQualifiedName~JvmLaunchTuningTest'
dotnet build '.\Plain Craft Launcher 2\Plain Craft Launcher 2.csproj' -c Release
```

构建警告或其他并行改动引起的错误需要单独归因；参数测试通过不等于完整游戏启动验证通过。
